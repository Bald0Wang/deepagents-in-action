# ch05 答疑知识库 · 子 Agent

## 核心概念

**task 工具**：主 Agent 用 `task` 把子任务委派给子 Agent。0.7.6+ **默认自带 `general-purpose` 子 Agent + `task` 工具**（与 ch04 的 TodoListMiddleware 不同，无需显式声明）。

**Context Quarantine（上下文隔离）**：子 Agent 在独立上下文里跑完中间过程，主 Agent 只收到精炼结果——主上下文不会堆满检索细节。

## 子 Agent 定义方式

**字典方式**：
```python
subagents=[{
    "name": "quick-lookup",
    "description": "用于简单、快速的查询，只需 1-2 次搜索，适合查找基本事实或定义",
    "system_prompt": "你是速查助手...",
    "tools": [web_search],
}]
```

**CompiledSubAgent**：把 `create_agent()` 编译好的 LangGraph 图包成子 Agent。
```python
CompiledSubAgent(name="calc-worker", description="...", runnable=custom_graph)
```
要求：图的 State **必须含 `messages` 键**。

## tools 继承语义（重要）

- 子 Agent **不指定 `tools`** → 继承主 Agent 的全部工具。
- 子 Agent **指定 `tools`** → **完全替换**（不是合并）。例如只给 `[calculator]` 就拿不到 `web_search`。

## description 决定路由

主 Agent 依据子 Agent 的 `description` 决定委派给谁。
- ✅ 具体：「用于简单、快速的查询，只需 1-2 次搜索，适合查找基本事实或定义」
- ❌ 模糊：「帮助处理各种任务」

好差同场时，具体描述会被选中；差描述的真实风险是**乱触发**（不是不触发）。

## 多子 Agent 协作模式

流水线：`data-collector` → `data-analyzer` → `report-writer`。
主 Agent 作协调者：`write_todos` 制定计划 + `task()` 逐步委派 + 整合输出。每个子 Agent 在独立上下文工作，主 Agent 只收到精炼结果。

## 结构化输出（response_format）

```python
class ResearchFindings(BaseModel):
    summary: str = Field(description="研究摘要")
    confidence: float = Field(description="置信度 0-1")
    sources: list[str] = Field(description="信息来源列表")

subagent = {..., "response_format": ResearchFindings}   # deepagents>=0.5.3
```
主 Agent 的 ToolMessage 收到符合该 schema 的 JSON，可 `json.loads` 直接用。

**版本坑**：`response_format` 内部会强制 `tool_choice`；`deepseek-v4-flash` 默认思考模式不支持，会 400。解法：给该子 Agent 单独指定非思考模型 `deepseek-chat`。

## 易错点

- 子 Agent 拿不到主 Agent 的对话历史（默认 isolated）；需要续写父对话用 `mode="fork"`（实验性）。
- `task` 的参数名在不同版本可能是 `name` 或 `subagent_type`，兼容读法：`args.get("name") or args.get("subagent_type")`。
- 子 Agent 的 `system_prompt` 要写清「只返回精炼结果」，否则它可能把原始数据全贴回来，隔离效果打折。
