# ch09 答疑知识库 · HITL

## 核心概念

`interrupt_on` 让敏感工具在执行前暂停，等人做决策。**需要 checkpointer**（保存暂停点，恢复必须用同一个 `thread_id`）。

## 四种决策类型

| 决策 | 效果 |
|---|---|
| `approve` | 用 Agent 原始参数执行 |
| `edit` | 改参数后执行（`edited_action`） |
| `reject` | 跳过执行，原因反馈给 Agent |
| `respond` | 人的回答直接成为工具结果（适合 `ask_user` 这类「问人」工具） |

## 关键 API（0.7.13 实测）

```python
r = agent.invoke({"messages": [...]}, config=cfg, version="v2")
# 中断信息：r.interrupts[0].value
#   = {"action_requests": [{name, args, description}...],
#      "review_configs":  [{action_name, allowed_decisions}...]}

agent.invoke(Command(resume={"decisions": [...]}), config=cfg, version="v2")
```

- `decisions` 数量/顺序必须与 `action_requests` **一一对应**（错配直接 ValueError）。
- 字段兼容：读 `arguments` 回退 `args`（本版实际用 `args`）。
- `edit` 载荷：`{"type": "edit", "edited_action": {"name": ..., "args": {...}}}`。

## when 谓词（条件中断）

```python
interrupt_on={
    "save_file": {
        "allowed_decisions": ["approve", "reject"],
        "when": writes_outside_workspace,   # 返回 True 才中断
    },
}
```
只拦真正危险的调用（如工作区外写入），安全调用自动放行，减少审批噪音。

## 批量中断

一次任务触发多个敏感工具时，中断合并成一个批次；`decisions` 按 `action_requests` 顺序一一对应（可以 approve 一个、reject 一个）。

## 子 Agent 独立审批

子 Agent 的 `interrupt_on` 独立配置，可覆盖主 Agent：
- 主 Agent：`interrupt_on={"read_secret": False}`（读不拦）
- 子 Agent：`interrupt_on={"read_secret": {"allowed_decisions": ["approve","reject"]}}`（读要审批）

## 文件系统权限中断

`FilesystemPermission(operations=["write"], paths=["/secrets/**"], mode="interrupt")` 与 `interrupt_on` 合并，一次人工审查同时覆盖自定义工具 + 受保护路径。中断动作格式相同。

## 低层 interrupt()

在工具或节点里直接调用：
```python
from langgraph.types import interrupt
approval = interrupt({"type": "approval_request", "message": "请审批：..."})
```
返回值 = `Command(resume=...)` 传入的数据。

## 重放机制（关键坑）

**恢复时节点从头重放**：`interrupt()` 之前的副作用会再跑一次。因此：
- 副作用要么放在 `interrupt()` **之后**；
- 要么做成**幂等**（upsert）。
- 不要在一个节点里 `while True` 反复 `interrupt()`（重放会连前几轮一起重跑）；把下一问写回 state，用条件边决定是否回到同一节点。

## 易错点

- 不加 checkpointer → interrupt 无法暂停/恢复。
- 恢复用错 `thread_id` → 找不到暂停点。
- `edit` 尽量保守（只改必要参数），大幅改写可能让模型重新评估计划。
- 拒绝副作用工具用 `reject`；`ask_user` 这类「问人」工具才用 `respond`。
- Node-style Hook（`after_model` 等）才是推荐的审批位置；Wrap-style 在节点内部，恢复时会连 handler 一起重放。
