# ch04 答疑知识库 · 任务规划

## 核心概念

**write_todos 工具**：Agent 用它在 state 里维护任务清单（`result["todos"]`），状态在 `pending` → `in_progress` → `completed` 之间流转。面对多步骤任务，规划提示词会引导模型先建清单再执行。

**版本关键差异**：课程说 `write_todos` 在 `create_deep_agent()` 时自动注入，但 **0.7.6+ 的默认中间件栈不包含 `TodoListMiddleware`**，需显式加：

```python
from langchain.agents.middleware import TodoListMiddleware
create_deep_agent(model=..., middleware=[TodoListMiddleware()], ...)
```

**Framework 层 vs Harness 层**：
- `create_agent()`（LangChain）：手动组合中间件，如 `TodoListMiddleware()` + `FilesystemMiddleware()`。
- `create_deep_agent()`（Deep Agents）：预设一套最佳组合。

## 两类中间件 Hook

- **Node-style**：`before_agent` / `before_model` / `after_model` / `after_agent`——独立图节点。
- **Wrap-style**：`wrap_model_call` / `wrap_tool_call`——包裹调用，可重试/缓存/降级。

## TodoListMiddleware 自定义配置

```python
TodoListMiddleware(
    system_prompt="## 任务规划规范\n1. 任何 >=2 步的任务都必须先 write_todos...",
    tool_description="创建/更新任务清单（团队规范：首项写文档，末项做核对）。",
)
```

自定义 `system_prompt` 会改变规划形态（如首项固定为写文档、末项为核对）。

## 任务清单的持久化

- 加 `checkpointer=MemorySaver()` 后，同一 `thread_id` 跨 `invoke` 保留 `todos`；换 thread 清空（上下文隔离）。
- 配置：`config={"configurable": {"thread_id": "todo-A"}}`。

## 规划 + 总结协同（北极星）

组合 `TodoListMiddleware` + `FilesystemMiddleware` + `SummarizationMiddleware`：
- `trigger={"messages": 6}` 提前触发总结（默认是 `("ratio", 0.85)`，1M 窗口跑不到，用消息数阈值低成本复现）。
- 判据：① `/conversation_history/` 出现存档文件（总结触发）；② `result["todos"]` 仍包含全部任务（清单未被破坏）；③ Agent 仍能按清单完成剩余任务。

## 易错点

- **不加 `TodoListMiddleware` 就没有 `write_todos` 工具**（0.7.6+）。
- `todos` 只在结果里出现于规划类任务；简单任务可能不触发规划。
- 默认规划提示词通常要求「≥3 步」才规划；给 2 步任务可能不生成清单，要显式配置或给足步骤。
- `TodoListMiddleware` 的 `system_prompt` 会与主 Agent 的 `system_prompt` 叠加。

## 版本提示

- 实测 deepagents 0.7.6 需显式注入 `TodoListMiddleware`；`SummarizationMiddleware` 来自 `deepagents.middleware`。
