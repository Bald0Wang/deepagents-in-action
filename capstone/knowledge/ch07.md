# ch07 答疑知识库 · Skills

## 核心概念

**Skill = 一个目录**，核心是 `SKILL.md`（YAML frontmatter + Markdown 正文），可选 `references/`（参考资料）与 `assets/`（模板资产）。

```markdown
---
name: code-review
description: 当用户要求审查代码质量、安全性或性能时使用此技能。执行结构化代码审查并输出报告。
---

# code-review
## Instructions
1. 用 read_file 读取 /skills/code-review/references/checklist.md ...
```

## 规范要点（Agent Skills Specification）

- `SKILL.md` 必须有 YAML frontmatter。
- `name` 必填：小写字母/数字/连字符，1-64 字符，**且与父目录名一致**。
- `description` 必填：非空，≤1024 字符。

## 三级渐进式加载

| 级别 | 时机 | 内容 |
|---|---|---|
| Level 1 | 启动 | frontmatter 的 `name` + `description` 注入系统提示词 |
| Level 2 | 匹配后 | Agent 主动 `read_file` SKILL.md 正文 |
| Level 3 | 按需 | 正文引用到的 `references/` 与 `assets/` 才被读取 |

**证据**：工具调用序列里能看到 Level 2 `read SKILL.md` → Level 3 `read references/... + assets/...`。

## description 质量

- ✅ 具体触发条件：「当用户要求审查代码质量、安全性或性能时使用此技能」
- ❌ 模糊：「帮助处理各种任务」
- 差描述的真实风险是**乱触发**：单独在场时，审查任务也会错误地用它；好差同场时好描述胜出；无关问题零触发。

## 三种存储后端注入 Skill

| 后端 | 注入方式 |
|---|---|
| `FilesystemBackend` | 本地磁盘直读，`skills=["/skills/"]` |
| `StateBackend` | 经 invoke 的 `files` 参数注入，必须用 `create_file_data`（直接传 str 会报错） |
| `StoreBackend` | `store.put(namespace, key, create_file_data(...))` 写一次，跨线程共享 |

## 多源优先级（last wins）

`skills=["/skills_shared/", "/skills_project/"]`：同名 Skill **后面的覆盖前面的**（project 版生效）。

## 与子 Agent 的继承规则（0.7.11 关键发现）

- `general-purpose` 子 Agent：**自动继承**主 Agent 的 Skills。
- 自定义子 Agent **不声明 `skills`**：**没有** Skills 系统（不继承）。
- 自定义子 Agent **显式声明 `skills`**：有自己的 Skills 系统。

**准确判据**：Skills 的「继承」指**系统提示词中的技能列表**是否注入，不是文件能否读取——子 Agent 总有内置文件工具，能读到 backend 里的文件。让子 Agent 自报「系统提示词里有没有 Skills 列表」才准确。

## Skill 权限

- `FilesystemPermission(operations=["write"], paths=["/skills/**"], mode="deny")`：只读（读得到、写不进）。
- `mode="interrupt"`：写 `/skills/**` 暂停等人工审批。
- 恢复格式：`Command(resume={"decisions": [{"type": "approve"}]})`。

## 易错点

- frontmatter 的 `name` 与目录名不一致 → 规范校验失败。
- `StateBackend` 注入 Skill 必须用 `create_file_data` 包装内容。
- Skill 目录路径相对 Backend 根：`FilesystemBackend(root_dir=ROOT)` + `skills=["/skills/"]` → `ROOT/skills/`。
