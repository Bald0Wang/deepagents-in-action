# ch10 答疑知识库 · 沙箱执行

## 核心概念

**沙箱的本质是 Backend**：普通 Backend 只实现文件读写；实现 `SandboxBackendProtocol`（核心是 `execute()`）后，模型才会看到 `execute` 工具。

Deep Agents 在**每次模型调用前**检查 backend 是否实现 `SandboxBackendProtocol`；满足才注入 `execute`。

## 四原语（Provider 接入核心）

自定义沙箱只需实现 4 个原语：
- `execute(command, timeout=...)`
- `upload_files([(path, bytes), ...])`
- `download_files([path, ...])`
- `id`（属性）

`BaseSandbox` 会自动把 `ls/read/write/edit/glob/grep` 等文件工具构建在 `execute()` 之上。所以**提供商接入的核心通常就是可靠地实现 `execute()`**。

## 两个平面

| 平面 | 谁在操作 | 方法 |
|---|---|---|
| 宿主平面 | 应用代码（不经模型） | `upload_files` 播种输入、`download_files` 取回产物 |
| Agent 平面 | 模型 | `read_file` / `execute` / `write_file` |

**路径差异**：文件工具用虚拟路径 `/data/nums.json`；`execute` 的 cwd 是沙箱根，用相对路径 `python3 src/stats.py`——两者访问同一工作区文件。

## 大输出处理

- **截断**：输出超过 `max_output_bytes`（LocalShell 默认 100KB；`MAX_OUTPUT_BYTES` 500KB）→ `truncated=True` + 提示。
- **落盘分页（推荐）**：大输出重定向到文件，`read_file` 按 `offset`/`limit` 分页。**注意 `limit` 按行数限制**——把 60 万字符写在一行，`limit=2` 仍可能返回整条巨长行。

## 安全闭环三层

1. **凭证留在沙箱外**：Key 由宿主侧工具持有，不返回给模型、不写进工作区。
2. **execute + HITL**：`interrupt_on={"execute": {"allowed_decisions": ["approve","reject"]}}`，敏感命令人工审批。
3. **产物默认不可信**：宿主 `download_files` 后先扫描（提示注入/危险模式）再采用，命中则隔离/脱敏。

## 生命周期与作用域

- **Thread-scoped**：应用维护 `thread_id → 工作区目录` 映射（thread_id 本身不会自动隔离磁盘）。
- **Assistant-scoped**：多个会话共用同一目录（缓存/依赖跨对话保留，但要 TTL/清理策略）。
- **异常清理**：`TemporaryDirectory` 上下文管理器保证异常时也回收。
- **execute 返回值**：不只有输出文本，必须同时看 `exit_code`（0 成功 / 非 0 失败 / 124 超时）与 `truncated`。

## 本地 vs 远程的关键差异

1. `BaseSandbox` 的文件辅助方法用**绝对路径**——本地进程无法把沙箱根虚拟成 `/`（`write('/x')` 会真写系统根）。**这正是真实沙箱用容器的原因**：容器里的 `/` 就是沙箱根。
2. `LocalShellBackend` / `RestrictedSandbox` 都在**本机**启动进程，**不提供容器级隔离**。
3. `virtual_mode` 只影响文件工具的路径映射，**不能限制 Shell 的绝对路径**。
4. 命令黑名单只是字符串匹配，**不是真正的断网**。

## 易错点

- 别把 `LocalShellBackend` 当生产沙箱用——它能执行任意宿主命令。
- 下载批量结果要逐项判断 `content is not None`（`b""` 合法空文件为假值，用真值判断会误判失败）。
- `execute` 的 `timeout` 是单命令上限；超时返回 124。
- 沙箱产物（尤其含外部输入）视为不可信，进业务流程前要审查。
