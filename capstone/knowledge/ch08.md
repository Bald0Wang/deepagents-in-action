# ch08 答疑知识库 · 长期记忆

## 核心概念

**两种记忆**：
| 类型 | 载体 | 生命周期 |
|---|---|---|
| 短期记忆 | Checkpointer（对话历史） | 同 thread 记得，换 thread 忘记 |
| 长期记忆 | Store（`/memories/` 路由到 `StoreBackend`） | 跨 thread / 跨会话持久 |

**关键**：`StateBackend` 的文件也是短期的——换 thread 文件消失。要长期记忆，必须把路径路由到 Store。

## CompositeBackend 路径路由

```python
backend=CompositeBackend(
    default=StateBackend(),
    routes={"/memories/": StoreBackend(namespace=user_namespace)},
)
```
- `/workspace/` → 临时（换 thread 丢）
- `/memories/` → 持久（换 thread 在）
- **0.7.13 细节**：存进 store 的 key 会剥掉路由前缀（`/memories/prefs.md` → `/prefs.md`）。

## 三种作用域

| 作用域 | namespace | 效果 |
|---|---|---|
| 用户级 | `(user_id,)` | A/B 用户隔离 |
| Agent 级 | `(assistant_id,)` | 所有用户共享同一份 |
| 组织级 | `(org_id,)` | 组织内共享（常配只读） |

namespace 工厂（课程推荐三件套）：
```python
def user_namespace(rt):
    if rt.server_info and rt.server_info.user:
        return (rt.server_info.user.identity,)
    return (getattr(rt.context, "user_id", "local-user"),)
```

## memory 参数自动注入

```python
create_deep_agent(memory=["/memories/AGENTS.md"], ...)
```
- 启动时自动把记忆文件内容注入系统提示词的 `<agent_memory>` 段。
- Agent 用 `edit_file` 更新后持久化到下次对话（自我改进）。

## 四种实用场景

1. **用户偏好记忆**：对话 1 说偏好 → 对话 2（全新线程）自动应用。
2. **自我改进 Agent**：用户纠错 → `edit_file` 更新 `AGENTS.md` → 新对话遵循。
3. **知识库累积**：多次对话逐次追加同一文件。
4. **研究持续推进**：场景 3 的多文件版。

## 外部预填

应用代码写入记忆，不要手写底层 JSON：
```python
store.put(("local-agent",), "/AGENTS.md", create_file_data("# Agent 行为准则\n..."))
```
**前缀剥离**：CompositeBackend 把 `/skills/` 路由到 Store 时会剥掉前缀，所以 `store.put` 的 key 是 `/greeting/SKILL.md`（不带 `/skills/`）。

## 组织级只读

`/policies/` 路由到 org namespace + `FilesystemPermission(mode="deny")`：Agent 读得到、写不进。合规策略由应用代码写入。

## 存储格式（v2）

store 条目 `value` 含：`content`（完整字符串）、`encoding`、`created_at`、`modified_at`。

## 易错点

- `StateBackend` 不是长期记忆，别指望换 thread 还在。
- `StoreBackend` 必须给 `store=`（本地）或在 LangGraph 执行上下文里。
- namespace 工厂要处理 `rt.server_info` 为 None 的本地场景，否则报错。
- 情景记忆（搜索过去对话）、后台整合（Cron + 整合 Agent）需要 LangGraph 服务部署，本地不做。
- `memory=` 路径要和 backend 路由一致（`/memories/AGENTS.md` 对应 `/memories/` 路由）。
